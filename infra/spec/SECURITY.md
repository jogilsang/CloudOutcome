# Security contract v0.2

- Accept aggregate metrics and synthetic/pseudonymous event identifiers only. Never put names, email addresses, phone numbers, addresses, payment data, national IDs, credentials or raw customer logs into source, fixtures, prompts, evidence, screenshots or persistent KPI fields. Owner means team label. Cognito usernames should be pseudonyms.
- Data schemas are allowlists. Unknown fields are rejected. API rejects several common sensitive patterns and avoids reflecting invalid inputs; detection is not exhaustive and cannot reliably identify personal names or every secret. Human review is still required before importing data. No real data is used in tests.
- Store API access tokens in browser memory only. OAuth code + S256 PKCE; verifier/state retained only for the short redirect transaction and removed on callback. Refresh/ID tokens are discarded. Config/hosting/API failures must not silently fall back to anonymous local mode.
- Require Gateway JWT validation plus access-token scope and workspace role. Never trust a tenant ID or role supplied in a client header/body. The app trusts only the Lambda integration event for its expected API ID. Direct Lambda invocation is privileged and restricted to deployment/control-plane principals.
- DynamoDB partitions derive from the authenticated subject; no scan permission. Version conflicts return 409; definition and content-free audit are transactional. Quota failures fail closed, including storage errors. Browser sample mode remains isolated and explicitly synthetic.
- No long-lived keys in repositories/pipelines. A local AWS CLI profile selects an existing developer session; service roles authorize builds/deployment. Do not print/read secret material into the transcript. .env, credential caches and local databases are ignored. Repository history, not only current files, must be reviewed before push.
- Account connection never accepts access keys, session tokens or codes from users. The workspace's External ID is generated server-side and is not accepted from clients. The runtime role may assume only `OutcomeLensReadOnly-*` roles; the published template grants list/describe and `cloudwatch:GetMetricData` only, and deleting its stack revokes access. Assume/read failures return fixed messages because SDK errors can contain another account's principal ARNs.
- The only anonymous API route is `GET /api/public/{proxy+}`. It requires the trusted gateway context, rejects other methods, and serves a precomputed snapshot whose account ID and non-OutcomeLens resource names are masked. Stage throttling bounds it; it does not call AWS per request.
- Platform and pipeline changes require tests tied to acceptance IDs. IAM wildcard exceptions for dynamic resource IDs are documented in DEPLOYMENT.md; they are not described as strict control-plane isolation. Production/customer launch needs a separate-account review.
- Automatic deployment is authorized by the user. No manual delivery gate is inserted. Automated security/artifact/change/smoke gates stop bad releases; pipeline bootstrap and remote runtime behavior still need actual AWS validation.
